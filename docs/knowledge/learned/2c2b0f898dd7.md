Yes, generated services can be internal-only (no public ingress) via `auth(service)` contracts, which derive `INTERNAL` exposure [datrix/docs/architecture/architecture-overview.md:663].
Services with no HTTP/GraphQL surface derive `NONE` exposure [datrix/docs/architecture/architecture-overview.md:663].
Non-HTTP services exist as workers and jobs; Docker uses `-queue-worker` clones for queue workers [datrix-codegen-docker/docs/architecture.md:749].
Docker also supports scheduler/consumer types which emit no replicas, implying non-HTTP job/worker roles [datrix-codegen-docker/docs/architecture.md:750].
Azure realizes `INTERNAL` services with private endpoints and no public network access [datrix-codegen-azure/docs/architecture.md:829].
AWS realizes `INTERNAL` services by omitting public LB targets, restricting ingress to east-west VNet traffic [datrix-codegen-aws/docs/architecture.md:198].
