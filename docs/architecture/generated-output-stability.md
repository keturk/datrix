# Generated Output Stability — No Stored Snapshot, No Blessing

Datrix is a code generator, so its most important behavioural contract is: **the same `.dtrx`
sources, generated with the same code, produce the same output.** For a long time the repo tried
to prove that with a stored snapshot — a committed per-file sha256 manifest of a reference
example's generated tree, compared on every run and "re-blessed" after every intentional
generator change. That instrument is gone, deliberately, and this document records why and what
holds the contract instead.

## Why there is no stored output baseline

A snapshot test can decide exactly one thing: *output changed*. It cannot decide whether the
change was intended — intent lives only with the author at the moment of the change. The whole
value of the instrument was therefore the human review of the diff at bless time. In a repo where
generators change daily, that review did not happen: the observed workflow was "gate red →
re-bless", which records whatever the generator did last and makes a regression
indistinguishable from progress. Baselines that nobody re-blessed drifted for a month across all
four registered languages (85 changed files on one example, nobody able to say which were
intended), and the hash-manifest form was unreviewable in git anyway — a 200-line diff of
sha256s with the real content only in a local cache a fresh clone never has.

A baseline nobody maintains detects nothing and looks like protection. A baseline everybody
re-blesses on sight detects nothing either. Both cost a bless step per generator change. So:

- **The repo commits no snapshot of generated output** — no hash manifests, no path manifests,
  no generated trees.
- **There is no bless / re-bless / regen-baselines step**, and no script that writes one.
- **No gate compares generated bytes against a stored reference.**

## What holds the contract instead

Every remaining check has a verdict that does not require knowing the author's intent:

| Property | Where it is decided |
|---|---|
| Generated output compiles and its own tests pass | `generate.ps1` at `STANDARD` (compile pass per language), `run-complete.ps1` (generated project's unit + spec tests) |
| Generation is deterministic — same code, N runs, one outcome | `datrix/scripts/test/java-generation-determinism-gate.ps1` |
| Every language emits the same set of domain roles for the same example | `datrix/scripts/test/artifact-role-parity-gate.ps1`, read from the **live** generated corpus (below) |
| Every language declares a stance on every domain and realizes what it declares | `supported-domain-parity-gate.ps1`; the testkit's domain self-consistency gate inside each language package (declaration ↔ registration ↔ fixture output) |
| A specific generator decision is preserved or ported | A test beside that code in the owning package, asserting the rendered output for a fixture |

The last row is the replacement for "byte-identical output on the reference example": a claim
about *one* decision is proven by *one* test that renders the construct and asserts the bytes
that matter. A test proves the invariant forever and fails the next person who breaks it; a
corpus-wide hash proved it once and evaporated at the next bless.

## The artifact-role gate reads the live corpus

`artifact-role-parity-gate.ps1` is the one repo-level gate that still needs a whole-corpus view
of generated output, and it gets that view **without storing anything**: it reads the generation
pipeline's own per-target manifests (`.datrix/manifests/<target>.json` — the files each target
wrote, plus a `generated_at` stamp) from the trees `generate.ps1` writes under
`<workspace>/.generated/<language>/<runtime>/<provider>/<example>/`.

Consequences, stated plainly:

- The gate is exactly as current as the local corpus. It prints every language's oldest and
  newest `generated_at` stamp so a reader can see what was compared.
- It **refuses to run** (exit 2) when any registered language's corpus is incomplete — a
  registered example with no generated tree and no entry in
  `scripts/config/parity-known-nongenerating.json` — naming every missing pair. A partial corpus
  would make every absent example's domains read as "never exercised" and silently shrink the
  comparison, so fail-closed is the only honest option.
- Generating the full corpus is `generate.ps1 -All -L <language>` once per registered language.
  That is a phase-boundary act Jon runs; it is hard-blocked for agents.
- `parity-known-nongenerating.json` is the only sanctioned gap: an example the real generator
  cannot build today, with a reason and a follow-up. A parked pair that *does* have a generated
  tree is a stale entry and fails the gate — the recorded defect is fixed, delete the entry.

## Stating acceptance for a refactor

A refactor's acceptance property is stated as a **decidable check**, never as "generated output is
byte-identical":

- A behaviour-preserving hoist or port: a test beside the shared builder (or the ported role)
  that renders the construct for a fixture and asserts the output, plus the per-symbol negative
  check that no private copy survives. Regenerate the reference example in the affected language
  and read the result while you work — that is inspection, not a stored proof.
- A performance or structure refactor (compute once instead of N times): object-identity tests
  proving reuse, plus deletion of the per-iteration path those tests would otherwise still
  exercise. There is no benchmark harness under `datrix/scripts/`, so a timing number is not a
  provable property.
- A change touching a **shared** package (`datrix-common`, `datrix-codegen-common`, any contract
  every generator consumes): the affected closure's package suites, every language, not just the
  one the author was working in. A shared helper consumed by a package the author never ran is
  exactly how a "neutral" refactor ships a change.

`datrix/scripts/dev/compare-generated.ps1` compares `.generated` against `.generated_saved` at
feature level — presence of known content patterns, not a byte-level diff. It is a development
aid, not a proof of anything.
