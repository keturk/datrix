# Pack: Codegen Engine — Transpiler, DAL generator, Stage Boundaries

**Read when:** you touch the transpiler (`StagePipeline`, `NameResolver`, `QueryExpander`, `LanguageTranspiler`, `TranspileContext`/`FileScope`/`TranspileResult`), a backend generation domain or its `.dal` declaration, DAL generator output paths or escaping, `#"..."` interpolation, or SQL literal quoting.
**Not for:** deciding what a target must realize ([parity-and-obligation.md](./parity-and-obligation.md)).
**Core map:** [architecture-cheat-sheet.md](../architecture-cheat-sheet.md)

## Transpiler Pipeline (per file)

```
Stage 1: NameResolver     -> ResolutionTable (id(ast_node) -> ResolutionInfo)
Stage 2: QueryExpander    -> updated table + query annotations
Stage 3: LanguageTranspiler (Python / TypeScript / …) -> TranspileResult (code + imports + flags)
```

`StagePipeline` in `datrix_codegen_common.transpiler` runs Stages 1–2 and configures the emitter; templates call the language transpiler for DSL bodies. Details: [code-generation.md](../../../../datrix-common/docs/architecture/code-generation.md), [datrix-common architecture](../../../../datrix-common/docs/architecture.md#transpiler-architecture-staged-pipeline).

| Category | Type | Lifetime |
|----------|------|----------|
| Config | `TranspileContext` | Per service; frozen |
| Per-file state | `FileScope` / language subclass | Fresh per emitted file; mutable |
| Upward artifacts | `TranspileResult` | Per visit; frozen |

**Generators read what analysis recorded about a body; they never walk one to learn it.** Which functions a service emits, which peers its code calls, which builtins and entity writes a body makes are recorded facts, and the reads that answer them are the ones listed in the facts table of [pipeline-stages](./pipeline-stages.md) ("Body analysis"). The few deliberate walks left in `datrix-codegen-*` sources are a closed, categorized allowlist that `datrix/scripts/gates/repo-hygiene/no-body-walk-gate.ps1` holds exactly (and `guard-code-standards.py` holds on every edit).

**AST dispatch:** `ExpressionVisitor[T]` / `StatementVisitor[T]` + `node.accept()` for expressions/statements (as `TypeVisitor[T]` for types); `CallTargetEmitter` + `dispatch_call()` for call targets — see [datrix-common-api — Transpiler modules](../../../../datrix-common/docs/datrix-common-api.md#transpiler-modules).

## Declared Emission — Every Backend Domain Is a DAL generator Declaration

[Decision 59](../architecture-overview.md#decision-59-declared-emission-for-backend-generators--every-domain-a-declaration-items-not-emissions-adopted) — Adopted.

- **One shape.** A backend domain is `each <item-target> [where call <predicate>] { context <Type> from <builder>; <lang> <name> { template "<t>" => "<path>"; [when call <gate>;] } … }`, nested as the items nest. Its Python is only its context builders, gates and filters (plain functions bound by name from the iteration scope); the builder carries the preconditions and builds the shared typed context where the domain has one. No per-domain micro-generator, hooks class or orchestrator exists in a backend package (`datrix_codegen_common.testkit.gates.domain_machinery_census`, run in each backend's suite).
- **Items, not emissions.** A computed collection is an item-yielding `IterationTargetSpec` (`resolver_ref`); a resolver returns model items, never `GeneratedFile`s, and a `builder` file clause supplies `str`/`bytes` content only — the kernel refuses both shapes. A resolver must declare its return type, and one whose declared type names `GeneratedFile` (or a subclass, in any generic argument) is refused when it is loaded, before it ever runs (`iteration_targets.require_item_yielding_resolver`).
- **Paths are declared.** Static path templates over sanitizing path attributes; a domain's structural glob derives from them or from its committed `structural "<glob>";` line — never from a class attribute. Every placeholder is resolved against its file's scope at definition load (`dgen.path_placeholders`), so an attribute nothing answers fails the load, not a generation. A generation declares each path once: the executor refuses a repeated path naming its producing declarations, and an application-level domain in a per-service generator declares `renders once;`.
- **`.dal` resources.** Each target's definitions are `dgen/generator.dal`, loaded by `generator_definition_file`; no DAL generator source lives in a docstring.
- **Every domain is declared.** A domain declares at least one file clause and carries no `builder` line; the shared emission-path gate (`check_every_domain_declared_or_f2_exempt`) refuses any domain that does not, unless a runtime reason a declaration can never execute is recorded for it in the language's F2-exempt map.
- **A declaration's decisions are read as cases.** A file rendered from a declaration records its context (`GeneratedFile.render_context`), so a fact about a generator's decision is one `context` case row (the field of that context), a `surface` row (one parsed unit of the file), a `paths` row (the declared path set under a literal prefix) or a `builder` row (a target's typed builder, registered from its own `tests/`) -- never a substring of the rendered text. Whole-tree parse validity is not a case: the `generate` stage syntax-checks every file of the generation with the package's own declaration (`GenerationSyntax`, the validators and unchecked languages its syntax test passes) before any case reads it. A new target registers its parser family, stages and builders from its own `tests/conftest.py`; nothing in `datrix-testing` changes ([unit-test-guidelines §4](../../../../datrix-common/docs/contributing/test-guidelines/unit-test-guidelines.md#decision-facts-as-cases)).

## Internal Documents — One Language, DAL

[Decision 60](../architecture-overview.md#decision-60-datrixs-internal-dsls-are-one-language-dal-parsed-by-lark-adopted) — Adopted.

Every internal declarative surface is a DAL document kind owning one decision family: `generator.dal` (generator definitions), `emit.dal` (builtin emit routing), `dependencies.dal` (per-language dependency tables), `realization.dal` (per-platform cell → plan builder and emitters). One strict-LALR Lark grammar (`datrix_codegen_kernel.dal`) gives every kind one syntax, lexical layer and error model; the registries rows validate against stay typed Python. No package constructs a table, row or cell outside its loader — the `datrix_testing.conformance.dal_authored_tables` gate pins each package at zero. Grammar and checks per kind: `datrix-codegen-kernel/docs/reference/dal.md`.

**Every row is an item.** The load-time checks prove each document closed as a whole; the per-row half is a table contract each owning package registers from its `tests/conftest.py`: every file declaration of a target's `generator.dal` (`datrix_codegen_kernel.dgen.file_rows`: static path template contained, every reference resolved to a callable, every iteration target registered, file language in the target's vocabulary), every row of an `emit.dal` (routing under facts matching exactly its predicates reaches its marked adapter; the target's emission of a matching call parses), every `BUILTIN_REGISTRY` row the target is obligated to and every type-map entry. The registration is round-tripped: the language completeness gates (`run_all_language_completeness_gates(plugin, session_registry().tables())`) and each client target's own test (`check_builtin_matrix_cell_registered`) fail when the target registered no cell of the builtin matrix. A target's generator definitions are a value its plugin holds: `DalGeneratorTarget.generator_definitions()` compiles them on first use and memoizes them on the instance, `target_definitions(<target>)` is the one by-name resolution for tooling with no plugin instance, and a set that is empty, names another target or carries a definition twice is refused (`require_target_definitions`) ([unit-test-guidelines, Table rows](../../../../datrix-common/docs/contributing/test-guidelines/unit-test-guidelines.md#table-rows)).

## DAL generator Engine Hardening

[Decision 42](../architecture-overview.md#decision-42-dal-generator-engine-hardening--output-path-containment-sanitized-path-attributes-one-escaping-home-and-the-interpolation-rule-adopted) — Adopted.

Every DAL generator output path is validated at construction on both render sinks by one shared containment guard (rejects `..`, absolute, drive, UNC). Path attributes resolve only through sanitizing case forms; raw/`original`/plugin names are display-only. Cross-target literal escaping has one home, what a reader cannot see is one set (`datrix_common.utils.hidden_text.hidden_in_source`: every code point that is not printable, every Default_Ignorable_Code_Point of the module's UCD table, and U+2800 BRAILLE PATTERN BLANK; its corpus is `datrix_testing.hidden_text_corpus`, and `gates/repo-hygiene/hidden-code-point-gate.ps1` holds every file under `datrix-codegen-*/src` free of it other than TAB, LF and CR), no such code point stands raw in an emitted string literal of any language (`datrix_common.utils.hidden_text`: `escape_hidden(text, form)` spells each one in the form its grammar decodes -- `EscapeForm.UTF16_UNITS` writes `\uhhhh`, an astral code point as a surrogate pair, for TypeScript/JavaScript and JSON; `EscapeForm.SIZED` writes `\xhh` / `\uhhhh` / `\Uhhhhhhhh` as `repr` does, for Python, whose reader would decode a pair as two lone surrogates; `EscapeForm.BRACED` writes `\u{h…}` for Bicep and Dart; `EscapeForm.CHARACTER_REFERENCE` writes `&#xh…;` for XML and template markup; both with lowercase digits and no leading zeros; `EscapeForm.PLIST_UNITS` writes `\Uhhhh` per UTF-16 unit, an astral code point as a surrogate pair, always four lowercase digits (the reader takes up to four, so a hex digit after the escape stays text), for Apple old-style property lists (`.strings`, `project.pbxproj`); `EscapeForm.FOUR_OR_PLUS_SIX` writes `\hhhh`, exactly four lowercase digits, and a code point above U+FFFF as `\+hhhhhh`, exactly six, for a SQL Unicode-escape string constant (`U&'…'`), whose caller doubles `'` and `\` first; `EscapeForm.FOUR_OR_EIGHT` writes `\uhhhh`, and a code point above U+FFFF as `\Uhhhhhhhh`, exactly eight lowercase digits, for a TOML basic string, which decodes no surrogate pair -- in `datrix_codegen_kernel.generation.source_text`, `json_text` is `json.dumps(ensure_ascii=False)` with every flagged code point escaped inside strings, `toml_string` is a whole TOML basic string (`"…"`: backslash and double quote take their short escapes, then `FOUR_OR_EIGHT` spells every flagged code point, each control TOML forbids raw among them), and `python_string_literal` / `python_literal` are the one Python string and value literal (`repr`, then `SIZED`), shared by the Python generator and every platform that writes a Python operator script or runtime asset; each language's escaper escapes its own delimiters and the backslash, then applies `escape_hidden` with its form, and Python never emits a raw `r"..."` literal from a value; a literal whose grammar has no escape, such as a PowerShell single-quoted string, passes its value through `refuse_hidden(text, grammar, where)`, which raises `GenerationError` naming the grammar, the declaration, the first hidden code point as `U+HHHH` and its index), no such code point stands raw in a generated comment, doc comment, docstring or database comment either (a comment has no escape grammar, so each comment writer passes every physical line through `datrix_common.utils.hidden_text.visible_text`, which writes each flagged code point other than LF as the visible text `[U+HHHH]`, uppercase hex, four digits, six for an astral code point; every comment writer breaks lines only at CRLF, CR, LF, U+2028 and U+2029 through `datrix_common.utils.comment_text` -- `comment_physical_lines` gives one comment line per physical line, as every `SyntaxEmitters.emit_comment` and the SQL `--` writer `sql_line_comment_lines` write them, and `comment_line_text` folds them into one with a space, registered on every `TemplateGenerator` as the `comment_line_text` filter for a value a template places in a one-line comment -- and never borrows a string literal's escape), dialect encoding sits behind `SQLDialect.quote_literal` and `quote_identifier`, which return the dialect's rows (`datrix_rdbms_schema.sql_lowering.dialect_rows`, the one home of a dialect's quoting, keyed by DDL dialect; a dialect with no rows raises `LookupError`): the string row writes a value holding a code point `hidden_in_source` flags in its engine's escape form (PostgreSQL `U&'…'`, `EscapeForm.FOUR_OR_PLUS_SIX`) and every other value as the standard literal, and the identifier row (`sql_quoted_identifier`) refuses an embedded `"` or NUL rather than doubling it, and a dialect that cannot encode raises `GenerationError` instead of quote-doubling. Every generated text file is checked where it is constructed: `GeneratedFile.__post_init__` (kernel `generation/generator.py`) refuses any code point `hidden_in_source` flags other than TAB, LF and CR with a `GenerationError` naming the file, line, column and `U+HHHH`, so a site no escaper reached stops generation on every target instead of writing the code point raw; a binary file (`GeneratedFile.from_bytes`) is not checked, and no file is excused. The set of sites is proved by a run, not a census: datrix-cli's `tests/integration/pipeline/test_hidden_code_points_corpus_run.py` generates the bundled `hidden_code_points` project (every author free-text slot holds the hidden-text corpus) once per registered language, deployment platform and client target, all enumerated from plugin registration and asserting `registered − exercised = ∅`, and every run must complete, so a site no escaper reached fails with the seam's error naming file, line, column and code point; the slots analysis or generation refuses (an enum value `ENUM012`, a route path `API016`, the `.dcfg` values a single-quoted PowerShell string carries) each have their own failing input and are asserted to stop with their own diagnostic. DSL interpolation has one form, `#"..."` / `#'...'` with `{expression}` (`FStringNode`/`InterpolationNode`), and flows only through the validated expression visitor (conformance test over every generator package, counted exemption baseline); a plain string literal never interpolates on any target, so `#{...}` in it is literal text that analysis does not resolve and every language emits as written.
