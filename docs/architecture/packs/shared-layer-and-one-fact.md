# Pack: Shared-Layer Consolidation — One Fact, One Home

**Read when:** you move, hoist, or deduplicate code; add a helper that another package may already have; a duplicate-body, shared-vocabulary, shared-target-name, or manifest-import gate goes red; you decide which package a new module belongs in.
**Not for:** deciding whether two targets *should* behave alike ([parity-and-obligation.md](./parity-and-obligation.md)).
**Core map:** [architecture-cheat-sheet.md](../architecture-cheat-sheet.md)

- **Code with a shared home has exactly one definition.** `shared-home-body-gate.ps1` matches normalized function bodies against every public function of datrix-codegen-common, datrix-codegen-kernel and datrix-common (decrease-only pins in `shared-home-body-baseline.toml`, plant/observe/revert self-test first). A hoist removes *every* private copy and is proven by a test that renders the hoisted construct, never a green suite alone; the repo keeps no stored snapshot of generated output ([generated-output-stability.md](../generated-output-stability.md)).
- **Vocabulary ratchets:** `check-import-boundaries.ps1 -CheckSharedVocabulary` (no language package redeclares a member set from `datrix_codegen_kernel.enums` or the declared canonical homes; baseline empty) and `-CheckSharedTargetNames` (no type/field/alias in `datrix-codegen-common`/`-kernel` carries a registered language name or its `name_tokens`; one reviewed exemption). A member set declared in two packages is a baseline entry with a written reason, never silence.
- **Dependency edges:** no hoist adds one. `manifest-import-parity-gate.ps1` holds every manifest equal to its import set in both directions, hard zero. `datrix-codegen-sql` and `datrix-codegen-component` depend on the kernel and never on `datrix-codegen-common`.
- **Placement:** platform-shared algorithms live in `datrix-common`/`datrix-codegen-kernel` (docker and azure do not depend on codegen-common); Python/TypeScript helpers in `datrix-codegen-common`; Angular/Flutter helpers in `datrix-codegen-common` generation beside `ui_contract`/`client_contract`. A hoisted function takes the per-language piece (caser, path renderer, type resolver, escaper) as a parameter and never branches on a language or platform name. A shared raise site takes the caller's own exception class.
- **Reuse the declaration that exists:** casing routes through `LanguageProfile.naming` casers; `Service.iter_callable_bodies()` is the only service-body enumeration; topological sorts use `graphlib`; `SourceCursor` (`datrix_common.source_syntax`) is the one cursor under the ConfigDSL and seed parsers.
- **A duplicate a design requires is a reviewed baseline entry, not a merge** (per-platform capability declarations, per-target realized-provider sets, per-adapter operation sets). **A mechanism label is a hypothesis about code** — read the implementations before collapsing.
- **Security-bearing shared functions fail closed** (API-key resolution, machine identity, extern auth and URLs, notification realization, managed-key check), one negative test per rule.
