# Pack: Frontend Clients and Complete Applications

**Read when:** you touch Angular/Flutter (or any client target), the client or UI contract, the `app` container, generated browser/mobile clients, route manifests, UI diagnostics (`UI0xx`), or web security headers.
**Not for:** backend auth semantics ([auth.md](./auth.md)).
**Core map:** [architecture-cheat-sheet.md](../architecture-cheat-sheet.md)

Decisions [43](../architecture-overview.md#decision-43-frontend-api-client-generation--browser-clients-emitted-from-the-same-dsl-as-the-backend-approved--implementation-in-progress) · [48](../architecture-overview.md#decision-48-complete-applications-in-datrix--web-and-mobile-frontends-from-the-same-dsl-as-the-backend-approved--implementation-in-progress) — Approved, implementation in progress. Decision 48 supersedes Decision 43's statement that components, pages, forms, routing, guards and view-model state are not generated.

- **Two layers:** a framework-neutral **client contract** (and UI contract) in `datrix-codegen-common`, and one **renderer package per frontend target** (an artifact-phase `datrix.generators` plugin, not a `datrix.languages` plugin). Activation is a declared config fact: the system config's base block names frontend targets as open identifiers validated against installed client-target plugins. The emitted client's language belongs to the target package; `--language` selects the backend only.
- **Client/gateway agreement:** a two-directional set comparison against the shared public-route enumeration; every browser-reachable route is a client method or a counted exemption. Machine-only surfaces (hidden, service, webhook) are never emitted; classification branches on `AuthMode` with a fail-loud default, never on provider-tuple emptiness.
- **Derived, never restated:** wire names, query-param names, pagination parameter names (`offset_pagination_param_names` on `LanguageCapabilityDeclaration`, read from the resolved backend plugin) and handler names come from the backend's plugin and shared helpers. A UI declaration that restates or loosens a derived fact is an error. No sensitive/hidden field is ever derived or persisted.
- **No secret, token, tenant id, environment URL, or per-profile value in any client file** (byte-identical manifest hashes across profiles). Path parameters are percent-encoded; request-body encoding is decided (multipart for file upload), never assumed; every emitted type is mapped and every referenced type emitted, with no `any` default.
- **The provider manifest is metadata, not authorization.** Never narrow a client per consuming application.
- **Adding a frontend target is one new package**; no frontend-target name in shared code; no frontend target depends on a backend language package (a TypeScript frontend depends on `datrix-codegen-typescript-core`).
- **Complete apps (D48):** a top-level `app` container, same grammar and statement language as services; backend and frontend containers never share a file; every UI endpoint reference resolves to a real client route; a block of UI code behaves identically on every client target (behaviour-parity gate covers every transpiler-profile package); a surface a target does not realize fails before any file is written; UI-only capabilities never reach a backend body and vice versa; emitted web security headers are one declared set per platform; a custom domain is realized with a certificate or rejected, never ignored. Shell diagnostics `UI037`–`UI040`.
- **Paginated routes (`Page<T>`):** a route returning `Page<T>` answers the envelope `{items, total, offset, limit}`; the Angular client types it `Observable<Page<T>>` (`core/page.ts` in the api-contract library) and the Flutter client `Future<Page<T>>` (`lib/api/core/page.dart`). `PagedBinding` (Angular `paged-binding.ts`, Flutter `core/binding.dart`) loads **one page per request** — no lookahead — and exposes `rows`, `total`, `offset`, `limit`, `pageCount`, `pageIndex`, `hasNext`, `hasPrevious`, `range`, `window`, `next()`, `previous()` and `goTo(index)`; it owns the position and size, so a UI call to a paginated route passes no `PageRequest` (`UI042`), and a later page answering with a different size restarts from the first page. The pager (table footer and paginated `list`) shows the range caption ("Showing 26–50 of 340"), previous, a numbered window and next. The window is **one algorithm**, `datrix_codegen_common.generation.ui_pager` (`PAGER_BOUNDARY_COUNT`, `PAGER_SIBLING_COUNT`, `pager_window`), rendered into both runtimes as `pageWindow` and tested against the same case table (`PAGER_WINDOW_CASES`) emitted into each target's generated tests. Framework strings `framework.showingRangeOfTotal`, `framework.pagination`, `framework.pageNumber`. A body-level call to a paginated route (from an `fn`, an event slot, a state initializer or a test body) is refused at analysis (`UI053`) on every client target, since a body owns no page position and has no envelope to read; bind the route with `data { }` instead. A test's `respond`/`respondError`/`called` names the binding's own call and is checked as that binding (`UI042`).
- **Static sites (`rendering('static')`):** an app prerenders to one HTML document per page and locale (diagnostics `UI043`–`UI048`, `UI052`; `datrix_semantic.validators.ui_static_checks`). A static app reaches nothing beyond its documents — no `uses`, `login`, `push` or runtime-config block (`runtime_config_blocks`, hoisted to `datrix_common.datrix_model.ui_runtime_config` so analysis and generation read one answer) — and every target it lists must build a web bundle. Locales are path prefixes (the default locale unprefixed); the route's locale is the session locale. Angular realizes it with `@angular/ssr` server routes (`app.routes.server.ts`: every routed path × locale, one document per key of a `from(...)` collection, redirects as meta-refresh, `404`), a server entry (`main.server.ts`), browser-side hydration without event replay (no inline script), a `SiteMetaStrategy` setting each head (description, canonical, `hreflang` alternates, Open Graph, robots), and persisted state restored after the first render. Angular's Router constructs the app's `TitleStrategy` while the Router is itself under construction, so nothing the strategy constructs (its messages, the session behind them) may resolve the Router then — doing so is a dependency cycle (NG0200) and a blank app: the session resolves the Router on use, a static app's `provideRouteLocale()` app initializer makes the session follow each navigation's locale, and `SiteMetaStrategy` reads the route from the snapshot the Router passes to `updateTitle`. `datrix-codegen-angular`'s `tests/integration/test_title_strategy_construction.py` and `test_static_rendering_emission.py` walk the emitted construction-time injections from each app's strategy and fail if the Router is reached. `scripts/build-app.mjs` is the one build entry every platform runs: it runs `ng build`, then for a static app requires and validates the build inputs, replaces the origin and robots placeholders, renames `404/index.html`, writes `robots.txt` and (when indexable) `sitemap.xml`, and fails on any inline executable script. `site-manifest.json` carries the profile-independent page list.
- **Build inputs and routing plan:** the origin and indexability of a prerendered site are build environment, never generated source (`datrix_codegen_kernel.generation.site_build_inputs`: `DATRIX_SITE_ORIGIN`, `DATRIX_SITE_INDEXABLE`; `AppWebConfig.indexable` defaults to `false`). Every platform that builds a static app passes exactly those keys and proves it (`require_site_build_inputs_supplied`). One `WebRoutePlan` (`datrix_codegen_kernel.platform.web_route_plan`) answers which paths exist, what an unknown path answers, which paths redirect and how files are cached and typed, and each platform renders it: nginx (`try_files`, `error_page 404 /404.html`, exact-location `301`s), a CloudFront viewer-request function plus 403/404 error responses, and Static Web Apps `routes`/`responseOverrides`. `WEB_CONTENT_TYPES` covers every extension a bundle can contain (including `avif` and `webp`), proven by `require_content_types_cover`. The plan's `paths` are the one set every platform serves: a static app's are its routed pages (`ui_derivation.routed_paths`, workspace sections included); a client app's add every path its router answers -- each redirect source and the hosted-login routes (`datrix_common.identity.hosted_login_paths.BROWSER_HOSTED_LOGIN_PATHS`: login, login callback, logout callback, forbidden), so the identity provider's redirect back to the app is answered `200`. No platform re-derives the set (Azure's `staticwebapp.config.json` rewrites, the CloudFront router function and nginx all read `plan.paths`). The hosted-login paths have one home: each client target renders its router/guard/session constants from it (`datrix_codegen_common.generation.ui_hosted_login.hosted_login_template_globals`), and every identity-provider registration derives a browser client's redirect and logout URIs through `browser_redirect_uri`/`browser_logout_uri`; `datrix-codegen-angular`'s `test_hosted_login_routes_served.py` compares the emitted route table with the plan in both directions.
- **Content, images, reveal (every app, every target):** `content` collections are authored as files (TOML front matter + Markdown), read once at generation time by `datrix_common.datrix_model.ui_content` and compiled in (`UI049`, `UI050`); `from(Collection)` pages enumerate their documents. Declared `image` assets and content image fields are encoded once by `datrix_codegen_kernel.assets.image_variants` (AVIF/WebP plus the source format, content-addressed, every raster re-encoded without metadata, byte-identical for a fixed input) and drawn by `ui-image` (Angular, `<picture>`) or `ResponsiveImage` (Flutter, WebP renditions); `image(asset, Msg.alt)` carries alt text and `: eager` marks the first image. `: reveal` is a flag realized by `UiReveal` (Angular) and `Reveal` (Flutter), skipped under reduced motion (`UI051`). Angular's ui-core reads browser globals only through `BrowserPlatform` (a census test holds this) and sanitizes Markdown through a `MARKDOWN_SANITIZER` token, so one ui-core serves the browser and the prerender.
- **Wire corrections:** bodies are camelCase on every target (a CQRS view response previously serialized snake_case — breaking for consumers of such endpoints); query keys carry the backend language's identifier casing, derived rather than hardcoded.
