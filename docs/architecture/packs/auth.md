# Pack: Auth — Route Kinds, API Keys, Revocation, Cross-Tenant, Media Type

**Read when:** you touch `auth(...)`, identity providers, guards, principals, tenant scoping, `@crossTenant`, `@produces`, API-key or revocation handling, or gateway edge credential policy.
**Not for:** frontend/client generation ([frontend-clients.md](./frontend-clients.md)) or secret-handling in emitted runtimes ([runtime-and-deploy.md](./runtime-and-deploy.md)).
**Core map:** [architecture-cheat-sheet.md](../architecture-cheat-sheet.md)

- **One auth behaviour per route kind (D53, Adopted).** The guard decision is computed once, in the kernel, from the route's `AuthContract`. Five kinds: `PUBLIC` (credential never read), `WEBHOOK` (its `verify(...)` only), `OPTIONAL` (absent → anonymous, presented-and-bad → 401), `AUTHENTICATED` and `SERVICE` (absent → 401); foreign provider, unadmitted principal type or no matching role → 403. Guards are per route (REST, serverless, GraphQL, WebSocket, derived nested routes), never global. Stage order: trusted caller → request tenant → authenticate → rate limit. `auth(...)` keys are closed (`providers`, `roles`, `profile`, `principalTypes`; IDN028); reading `Auth` in a public/webhook body is IDN029. REST, WebSocket and serverless request models reject unknown fields. Reason codes come from `AuthReasonCode` alone.
- **Inbound API-key provider (D13 amendment, Approved).** `provider = "apiKey"` verified by SHA-256 hash lookup at the single service owning the key entity, asked over the authenticated service channel with no caching (revocation and per-key rate limit are exact per request). Provider plan schema v4 is a union on `credential` (`"jwt"` | `"apiKey"`). Fail closed on every failure path (owner timeout/5xx → 503, invalid → 401, ambiguous credentials → 401 without a network call). The raw key never leaves the receiving service; tenant comes from the key row. Every gateway type realizes the per-route edge credential policy; the edge never validates the key itself.
- **Token revocation (D52, Approved).** `revocationMode` (`none` | `denylist` | `introspection`) is one step in each language's auth chain after verification and attribution: revoked → 401; undeterminable → 503 `revocation-unavailable` with `Retry-After`, never "not revoked". Until every language realizes it, config resolution refuses a non-`none` mode in one shared place. No policy or opt-out turns a revocation read into an allow.
- **Declared cross-tenant bodies (D49, Approved).** Tenant scoping stays fail-closed; `@crossTenant` is the only way a body reaches rows across tenants. Legal only on `auth(service)` or workforce-only role-gated endpoints, service/`rest_api` `fn`s, `on` handlers, `enqueue` consumers and `job`s (everything else is TEN003–TEN008). The tenant middleware is unchanged; each cross-tenant body logs `cross_tenant_access handler=… kind=…`. `tenant(<expr>) { … }` blocks are legal only in a `@crossTenant` body (TEN009/TEN010).
- **Route media type (D51, Adopted).** `@produces('<media type>')` on a REST/serverless endpoint returning `Bytes`/`Bytes?`; API013–API015 validate it (lower-case RFC 6838, charset rule, allowlist rejecting html/xml/script/multipart/message). The fixed binary header set (`nosniff`, CSP `default-src 'none'; sandbox`, `Content-Disposition: attachment`) is unchanged; the type is always a generation-time literal.
