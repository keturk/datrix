# Pack: Auth — Route Kinds, API Keys, Revocation, Cross-Tenant, Media Type

**Read when:** you touch `auth(...)`, identity providers, guards, principals, tenant scoping, `@crossTenant`, `@produces`, API-key or revocation handling, or gateway edge credential policy.
**Not for:** frontend/client generation ([frontend-clients.md](./frontend-clients.md)) or secret-handling in emitted runtimes ([runtime-and-deploy.md](./runtime-and-deploy.md)).
**Core map:** [architecture-cheat-sheet.md](../architecture-cheat-sheet.md)

Decisions [13](../architecture-overview.md#decision-13-managed-identity-provider-integration-adopted) · [49](../architecture-overview.md#decision-49-declared-cross-tenant-bodies-and-tenant-parameters-on-service-routes-approved--implementation-in-progress) · [51](../architecture-overview.md#decision-51-declared-route-response-media-type-produces-adopted) · [52](../architecture-overview.md#decision-52-token-revocation--one-check-per-auth-chain-realized-on-every-language-approved--implementation-in-progress) · [53](../architecture-overview.md#decision-53-one-auth-behaviour-per-route-kind--five-guard-kinds-one-chain-dead-identity-surfaces-removed-adopted).

- **One auth behaviour per route kind (D53, Adopted).** The guard decision is computed once, in the kernel, from the route's `AuthContract`. Five kinds: `PUBLIC` (credential never read), `WEBHOOK` (its `verify(...)` only), `OPTIONAL` (absent → anonymous, presented-and-bad → 401), `AUTHENTICATED` and `SERVICE` (absent → 401); foreign provider, unadmitted principal type or no matching role → 403. Guards are per route (REST, serverless, GraphQL, WebSocket, derived nested routes), never global. Stage order: trusted caller → request tenant → authenticate → rate limit. `auth(...)` keys are closed (`providers`, `roles`, `profile`, `principalTypes`; IDN028); reading `Auth` in a public/webhook body is IDN029. REST, WebSocket and serverless request models reject unknown fields. Reason codes come from `AuthReasonCode` alone.
- **Inbound API-key provider (D13 amendment, Approved).** `provider = "apiKey"` verified by SHA-256 hash lookup at the single service owning the key entity, asked over the authenticated service channel with no caching (revocation and per-key rate limit are exact per request). Provider plan schema v4 is a union on `credential` (`"jwt"` | `"apiKey"`). Fail closed on every failure path (owner timeout/5xx → 503, invalid → 401, ambiguous credentials → 401 without a network call). The raw key never leaves the receiving service; tenant comes from the key row. Every gateway type realizes the per-route edge credential policy; the edge never validates the key itself.
- **One gateway edge decision per endpoint and method.** `EdgeCredentialMode` (`datrix_common.deployment.edge_credential_mode`, one table over `AuthMode`) is what a gateway edge demands before forwarding a surface: `REQUIRED` (every other mode, any `:hidden` endpoint, an unlowered contract), `OPTIONAL` (non-hidden `auth(optional)`: no credential → forwarded, any credential presented → validated and a bad one refused, never skipped) and `NONE` (non-hidden `auth(public)` and `auth(webhook)`; a webhook's sender is verified by the service). The kernel's `EdgeCredentialPolicy` carries it (`jwt_required`, `validate_presented`, `api_key_headers`) per `PublicRoute`; WebSocket / GraphQL-subscription upgrades carry the same mode. Every realization decides per endpoint **and method**, never per path: nginx per request method inside one location (a method map, with an undeclared method taking the strictest declared mode), APIM per request method inside one routing `<when>`, API Gateway one HTTP API route per (method, path) so each route carries its own authorizer. The service-side guard still verifies every presented credential (the gateway is never the only check).
- **Token revocation (D52, Approved).** `revocationMode` (`none` | `denylist` | `introspection`) is one step in each language's auth chain after verification and attribution: revoked → 401; undeterminable → 503 `revocation-unavailable` with `Retry-After`, never "not revoked"; an open socket is re-checked every 30 seconds and closed 4401 or 1013. Every registered language realizes both modes (`datrix_common.identity.revocation` holds the shared constants and rule codes REV001–REV007; `auth/revocation.ts` / `revocation.py` are the modules), and config resolution no longer refuses a non-`none` mode. No policy or opt-out turns a revocation read into an allow.
- **Declared cross-tenant bodies (D49, Approved).** Tenant scoping stays fail-closed; `@crossTenant` is the only way a body reaches rows across tenants. Legal only on `auth(service)` or workforce-only role-gated endpoints, service/`rest_api` `fn`s, `on` handlers, `enqueue` consumers and `job`s (everything else is TEN003–TEN008). The tenant middleware is unchanged; each cross-tenant body logs `cross_tenant_access handler=… kind=…`. `tenant(<expr>) { … }` blocks are legal only in a `@crossTenant` body (TEN009/TEN010).
- **Route media type (D51, Adopted).** `@produces('<media type>')` on a REST/serverless endpoint returning `Bytes`/`Bytes?`; API013–API015 validate it (lower-case RFC 6838, charset rule, allowlist rejecting html/xml/script/multipart/message). The fixed binary header set (`nosniff`, CSP `default-src 'none'; sandbox`, `Content-Disposition: attachment`) is unchanged; the type is always a generation-time literal.
- **One tenant per connection, bound at the handshake.** A `websocket_api` and a GraphQL subscription of an `auth(required)`/`auth(optional)` handshake bind the service's one tenant after authentication and the contract checks, from the upgrade header (`header`) or the claims the auth chain verified (`jwt`) — never a frame, never a second token decode (`path` with a binding handshake is a generation error). `strict` refuses a missing value 401/4401 and a non-UUID 400/4400 (every enforcement); a message body that reaches a Tenantable entity takes the connection tenant (`websocket_message_tenant_source`), `auth(service)` reads the payload's tenant field, `auth(public)` binds none. The HTTP `jwt` tenant is bound by the route guard (Python `bind_connection_tenant`, TypeScript `AuthGuard` → `bindAuthenticatedTenant`) for `auth(required)`/`auth(optional)` routes only. Expiry clears principal and tenant before the 4401 close; there is no in-band re-authentication. Detail: `datrix-codegen-python/docs/tenancy-codegen.md`, `datrix-codegen-typescript/docs/tenancy-codegen.md`, `datrix-codegen-common/docs/architecture.md` (3b'').
- **Refusals and audit events have one vocabulary.** Every identity audit event name lives in `IdentityAuditEvent` and reaches templates only as an `AUDIT_EVENT_<NAME>` global (no template spells an `identity.` event or a `trusted_caller_` literal; a census test per language package holds it). Both languages log a trusted-caller refusal as exactly `identity.trusted_caller.rejected reason_code=<AuthReasonCode> path=<path>` at `warning` (an accepted token logs `identity.service_principal.authenticated` at `debug`) — never the `oid`, a token or exception text — and answer it as an opaque `unauthorized` / `forbidden` problem through the language's one registry-rendered responder, whose detail is the family title. Middleware that runs outside the exception handlers (trusted caller, tenant, API-key extractor) returns the responder's own response; the rate limiter's 503 / 500 answer `service-unavailable` / `internal` with the cause logged, not sent.
