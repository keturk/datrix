# Pack: Parity, Capability Obligation, Realization Conformance

**Read when:** two targets (languages, platforms, client targets) behave differently over the same source; you add or touch a `capability_gaps` row, a parity gate, a portable config field, or a telemetry/diagnostics setting; a gate under `datrix/scripts/test/` goes red.
**Not for:** hoisting duplicated code ([shared-layer-and-one-fact.md](./shared-layer-and-one-fact.md)) or plugin wiring ([target-plugins.md](./target-plugins.md)).
**Core map:** [architecture-cheat-sheet.md](../architecture-cheat-sheet.md)

## Parity and Obligation

Decisions [28](../architecture-overview.md#decision-28-cross-target-parity-enforcement--derived-gates-and-declared-capability-holes-adopted) · [29](../architecture-overview.md#decision-29-language-target-capability-parity-to-the-reference-surface-approved--implementation-in-progress) · [30](../architecture-overview.md#decision-30-platform-target-validation-floor-and-realization-parity-adopted) · [31](../architecture-overview.md#decision-31-mini-dsl-consolidation--declared-surfaces-replace-imperative-bypasses-adopted) · [44](../architecture-overview.md#decision-44-parity-by-construction--declared-universes-shared-plan-modules-and-declared-routing-on-the-language-axis-adopted) · [47](../architecture-overview.md#decision-47-language-axis-behaviour-parity--roles-behaviour-skeletons-and-the-best-realization-as-reference-approved--implementation-in-progress) · [55](../architecture-overview.md#decision-55-capability-level-obligation-counted-gaps-and-population-wide-parity-gating-adopted).

**A per-target difference in behaviour is a defect with N copies; only rendering differs per target.** Same validated `Application` in, same behaviour out.

- **Obligation exists only at the capability level** (block type, builtin group, DAL generator domain, portable config surface, observability category, notification channel, identity feature, push, web build, documented construct). A flavor/provider/product/topology a target does not offer is that target's vocabulary, not a gap; selecting it fails closed, naming what the target offers.
- **A gap** is a target realizing a capability by no implementation: one `capability_gaps` row (`surface`, `detail`; no reason field) on that target's own declaration. A row suppresses nothing; every gate keeps counting it. `capability-gap-ledger-gate.ps1` pins totals two-directionally in `datrix/scripts/config/capability-gap-baseline.toml`.
- **Repo-level gates** enumerate targets from entry points at runtime, self-test non-vacuity every run, refuse to pass with fewer than two targets, and derive inventories from registration, never hand-written lists.
- **No parity gate sets a target aside by declaration or committed file.** A capability declaration carries no "emitted only on demand" fact and no gate reads one; a gate that compares role sets (`artifact-role-parity-gate.ps1`, `behaviour-parity-gate.ps1`) takes its population from registration and skips a role only when the domain's own pattern matches nothing anywhere in the target's generated footprint (corpus-vacuous, recorded in `corpus-vacuity-records.json`). The artifact-role gate's provider axis also reads, for a platform-gated domain (`datrix_codegen_kernel.parity.platform_gated_domains`: the domain linked to the very capability predicate its emission path calls, such as `cdn` → `provides_cdn_cache_invalidation`), each platform's own declared answer: the role is not drift under a provider whose platform withholds the capability while every carrying provider's realizes it, and a tree carrying a role its platform withholds fails. That is a declared topology fact read on both sides, not a target set aside; a `capability_gaps` row never stands in for it. Two targets that emit a domain under different DSL triggers produce different artifact sets from one source, and the gates count that as drift. A committed file a gate reads holds reviewed hits, never target scope: `response-body-transform-exemptions.json` holds only `transform_exemptions` (one exact detector hit each) and the gate refuses any other key. Detail: the quick-reference sections for those gates and Decision 44 part D.
- **A gate that enumerates targets never names one, and never carries a per-target table.** How a target's generated artifact is read belongs to the target: a language supplies `LanguagePlugin.conformance_probes`, a platform `PlatformPlugin.declared_conformance_probes()`, and a client target (a generator whose descriptor sets `client_target`) the classmethod `declared_conformance_probes()` on its generator class, reading its own `clients/<key>/` subtree (the `datrix_codegen_kernel.parity.conformance_probes` Protocols `LanguageConformanceProbes`, `PlatformConformanceProbes` and `ClientTargetConformanceProbes`; the Protocol declaring a row's probe decides which axis of targets the row is read on; a missing or incomplete probe fails by name, an empty probe result fails as vacuous, every file read is contained under the generated root). Per-target *data* a reading needs (such as how the enum classifier's definitions are spelled) lives on the capability declaration. `documentation-realization-parity-gate.ps1` reads targets this way; every other probe-read fact is a parity row (next bullet). Each gate's self-test first runs `shared.registered_targets.target_references_in_module` over the gate's own source and fails on any import of a target package or any target name in a comparison, subscript, `.get(...)`, dict-key or `match` position. The per-language census gates (`dependency-declaration-ratchet-gate.ps1`, `migration-upgrade-op-family-gate.ps1`, `zero-environment-runtime-gate.ps1`, `field-error-path-parity-gate.ps1`) run the same self-scan; a reviewed per-language fact one of them needs (an exemption, a pinned count, a call-site count) lives in its baseline under `datrix/scripts/config/`, keyed by registered name, where an entry naming an unregistered target is stale and fails, and a live non-vacuity check derives its real sample from that baseline or the tree, never from a target pinned in the gate.
- **A parity fact over generated artifacts is a row, never a new gate module.** A fact read through a conformance probe ("every language answers `GET /api/v1/books` with 200 and the page envelope") is one row of `datrix/scripts/gates/parity/cases/<area>.parity.yaml`: a case row (`datrix_testing.cases.model.Case`, so the strict schema, the raw-secret refusal and the tag vocabulary apply) with `stage: parity`, `observer` a probe method, `input` the fixture (a registered example of `test-projects.json`, or for the header-set probe one of its two header-set fixtures), `selector` a facet of the probe's return plus its keys (a route's verb and path, an event, a header name; never a whole artifact), and `expectation`, always authored. `parity-cases-gate.ps1` reads every row on every registered target of its axis -- the axis is the Protocol that declares the observer -- and the facets and their readings are one table, `gates/parity/lib/parity_observers.py`. **Two verdicts:** the authored one decides (a reading other than the expectation is a `DIVERGENCE`, so every target agreeing on a wrong value fails, which a target-against-target comparison never caught); the mutual one informs (`DRIFT` names every target's reading when they differ, which says who moved when the expectation is the stale side). A target carrying the row's `capability: <kind>:<id>` gap is a failing `GAP`. A new parity fact is a row (`parity-cases.ps1 observe` / `new`); a reading no probe returns is a new Protocol method with one implementation per target plus a facet, still no gate; a new target is covered by implementing the Protocol, which the kernel resolver requires. A new gate module is reserved for a source census (it imports no probe), and `guard-repo-policy-edits.py` refuses a new probe-importing one. `response-body-transform-census-gate.ps1` is such a census: the transform a framework applies after serialization, which the response-body rows cannot see.
- **A value another writer produced is read by one rule per read kind, on every target.** During a rolling deploy, after a rollback, or through a shared block, the writer may be a newer version that carries a struct field this copy does not declare.
  - A **consumed message** (pub/sub event or queued message, at every consume site: block consumer, serverless or service-level subscription handler, queue worker or serverless queue consumer) is validated against the message's declared fields before handler code runs. A missing or mistyped declared field, or a malformed nested struct, fails the delivery. An undeclared field is dropped. Python uses a payload model with `extra="ignore"`; TypeScript uses `readPeerPayload` into a class-validator class with whitelist on and forbid-non-whitelisted off.
  - A **stored value** (struct column, cache entry, NoSQL document) is readable whatever fields a newer writer added, and a write-back keeps them. Python reads with `extra="allow"` and writes through `stored_form`/`stored_fields`. TypeScript stores the plain JSON object, except a struct column (a struct, or a collection of structs at any depth): that is bound to `StructJsonType`, which reads the stored JSON into instances of the generated struct classes, validates every declared field on read and on write, and keeps an undeclared field both ways. A declared field that fails its type fails the read or the write on every target (Python's `StructJSON` raises the same way); the message names the property path, never the value.
- **What a declared type accepts at a boundary is one rule per type, on every target.** Every domain scalar has one definition in `datrix_common.builtins.domain_formats` (a format, a range, or the target's native type), a sized text counts code points, and the `String` builtins count code points and trim Unicode `White_Space` (`datrix_common.builtins.text_units`). Every target renders each surface -- entity and struct fields, route parameters, collection elements and `Map` values, foreign keys, seed cells -- from those definitions, and the shared corpus `datrix_testing.domain_scalar_corpus` is run against the definitions and each target's rendering.
  - An **authorization artifact**, such as an approved tool call's arguments, is read exactly or refused.
  - A consumer never casts an unvalidated message to its type.
- **Config surfaces no target consumes are deleted**, not deprecated. Per-target behaviour is declared once; a declared surface is the only emission path (DAL emit-table predicate columns, shared test-generator plans, closed seed pipeline, queue/serverless block dispatch).
- **Language axis (D44, D47):** the domain universe is the *union* of what any language declares; every builtin row belongs to a capability group; a language's builtin capability is its `realized_builtin_groups` set; a single-step routing decision is a declared DAL emit-table row consulted *first* (`emit_function_for`). `behaviour-parity-gate.ps1 -Axis languages|platforms` groups functions by role, compares behaviour skeletons, and is pinned per axis in `behaviour-parity-baseline.toml`. **There is no reference language:** when copies disagree the shared implementation takes the strongest behaviour on four ordered axes — fails closed, reads everything the DSL declares, most secure, most correct output. A hoist follows parity, never precedes it. No function in a language package carries its own language's name (`name_tokens` per language).
- **Further gates (`datrix/scripts/test/`):** `block-realization-parity-gate.ps1`, `standing-conformance-gate.ps1`, `observability-axis-parity-gate.ps1`, `framework-header-parity-gate.ps1`, `problem-type-parity-gate.ps1`, `zero-environment-runtime-gate.ps1`. A generated-suite parity layer compares emitted test/pass sets per example at Jon's full-suite cadence, never inside an agent's fix. Tests are matched by a language-neutral case id the shared layer owns (`datrix_codegen_common.algorithms.test_case_identity`: every generated test family declares its case set once; each emission's `TestCaseCatalogue` reaches every language's template as `test_cases`, and a template may render only declared cases), never by framework name: pytest records the id as a `datrix_case` marker copied into a JUnit property, Jest as the test's own title.

## Portable Telemetry Volume and Realization Conformance

[Decision 32](../architecture-overview.md#decision-32-portable-telemetry-volume-and-platform-diagnostics-contracts-with-realization-conformance-adopted) — Adopted.

- Portable export-volume fields: `logging.exportLevel`, `metrics.exportIntervalSeconds`, trace sampling rate, and one `diagnostics { verbosity; retentionDays; dailyBudgetGb }` platform block projected by each platform. No platform defines its own retention or verbosity field. New fields default to today's effective behaviour.
- **A knob a target accepts is a knob it realizes.** Per-package perturb/regenerate/diff conformance (`datrix_testing.conformance.config_realization`): Tier 1 catches an inert field, Tier 2 a comments-and-strings-only change. A legitimately inert field is a reviewed exemption in the package's baseline (written reason, no field named twice). The gate proves its own non-vacuity every run.
- **(provider × target) realization is one fact per target**, read through `capability_resolution.declaration_for_language` / `declaration_for_provider`; never an assembled table in shared code.
